# Profile editor and driver entry UX

- Customer account settings are behind an **Edit profile** action beside **Book a ride**. The form mounts only when opened, so the dashboard no longer fetches or displays profile settings inline.
- One native dialog presents a centered desktop modal and a bottom-aligned mobile sheet. It provides an explicit close control, backdrop and Escape dismissal, native focus containment, focus restoration, scroll locking, responsive height and internal scrolling. Closing unmounts the editor and clears its password fields.
- Existing authenticated profile persistence and Supabase account-security checks are retained. Personal details/preferences and account security remain separate forms.
- Generic sign-in still routes by the verified server role. The login screen adds explicit Customer/Driver options, and the homepage adds a driver section. Driver-specific URLs retain intent through confirmation/recovery. A customer selecting driver sign-in receives an explanation rather than access to the driver portal.
- Approved drivers can activate sign-in using the email previously added by operations. Public registration never grants a driver role. Prospective drivers contact operations through the company's published WhatsApp/email/phone channels. There is no claim that an application was submitted or approved.
- Supabase redirect allow-list additions are documented in auth-setup.md. Hosted SMTP/email-link verification remains pending as previously agreed; no activation/reset email was sent in these UI tests.

Validation: all 66 automated tests (including three new redirect/role checks), TypeScript, lint and isolated production build passed. Browser checks passed real empty states, profile persistence from the modal, desktop centering, mobile sheet positioning/fit, close icon/Escape/backdrop, focus/scroll restoration, existing account-menu/alert controls, homepage driver entry, activation labels/placeholders, password visibility reset when switching modes, customer denial and verified driver routing. Temporary verification accounts were removed. Verification creates and removes temporary confirmed customer/driver identities; external payment, email, push and media delivery are disabled on the isolated server.
